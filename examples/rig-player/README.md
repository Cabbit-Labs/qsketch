# qSketch rig player

A small reference runtime for rigs exported with **File ▸ Export Rig for
Games…** (format: [`docs/RIG_FORMAT.md`](../../docs/RIG_FORMAT.md)). Plain
JavaScript, no build step, no dependencies.

| File | What it is |
|------|------------|
| `rig-runtime.js` | The posing math: curves, animation sampling, drives (gears), two-bone IK, part matrices, skins. Knows nothing about the DOM, so it is the piece to port to another engine. |
| `player.js`, `index.html` | A canvas player: pick an animation, play, scrub, change speed, show the bones. |
| `test.html` | Checks the runtime against the editor (see below). |
| `sample/` | A small character exported from qSketch (idle, walk with IK legs, wave); its arms and legs are meshes that bend at the elbow and knee. |
| `fixture/` | A rig using every feature, and the matrices the editor computes for it. |

## Run it

Browsers won't `fetch()` files from `file://`, so serve the folder:

```bash
python3 -m http.server 8000 --directory examples/rig-player
```

Open <http://localhost:8000/>. It loads `sample/rig.json`. To play your own
export either press **Open exported folder…** and pick the folder qSketch
wrote (it holds `rig.json` and `parts/`), or put the folder next to
`index.html` and open `?rig=my-export/rig.json`.

## Use the runtime in your own code

```js
const rig = QRig.load(await (await fetch("rig.json")).json());

// every frame:
const world = QRig.pose(rig, "walk", seconds);   // null for the setup pose
for (const part of rig.parts) {                  // already in draw order
  const m = QRig.partMatrix(rig, part, world);   // image pixels -> canvas
  ctx.setTransform(m.a, m.b, m.c, m.d, m.e, m.f);
  ctx.globalAlpha = part.opacity;
  // frame art: the picture changes with the document's frames
  ctx.drawImage(images[QRig.partImage(rig, part, "walk", seconds)], 0, 0);
}
```

`seconds` can be any value: looping animations wrap and others hold their last
pose. Blend names map to Canvas modes with `QRig.canvasBlend(part.blend)`.

## Does it match the editor?

Open `test.html` (through the server). It poses `fixture/rig.json` in the
setup pose and at 18 times in each animation, and checks every result: every
bone matrix, one part's matrix, and every skinned vertex of a mesh against what qSketch's
own rig code computed (`fixture/expected.json`). The fixture covers Bézier and
stepped easing, scale keys, a mesh weighted to all nine bones, IK with a keyed mix and a stepped bend flip, a
leg reaching out of range, a looping and a non-looping animation, times past
the end and a part attached to a bone.

The fixture, the sample and `expected.json` are generated by a Rust test, which
also fails when they are out of date. After changing the rig format or the
editor's posing, regenerate them with

```bash
QSKETCH_UPDATE_PLAYER=1 cargo test -p qsketch-core --test rig_player_assets
```

and run `test.html` again.

## Not covered

* Meshes are drawn as textured triangles with a slightly grown clip, which
  hides seams but is not a substitute for a real GPU mesh renderer. The test
  checks mesh vertex positions, not pixels.
* The sample only shows the Canvas 2D blend modes; Linear Burn, Subtract and
  Divide fall back to normal.
* Layer effects, masks and adjustment layers are not exported, so they are not
  played.
